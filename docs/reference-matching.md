# External reference → editable starting patch

This is the first useful reference-sound workflow, not an extension of the old model's accuracy claims. It runs directly from the JUCE editor and never predicts settings the plugin already knows.

## Use in Logic

1. Save/quit Logic and install the current build with `bash scripts/install-development.sh`. Start the existing backend once with `bash scripts/start-plugin-analysis.sh` (do not start a duplicate on port 8766).
2. Open the plugin. Set **Gate ms** to the reference's MIDI note-on → note-off duration (150–3000 ms). This is not total file length. The release tail should be included in the file.
3. Leave pitch at **Auto pitch**, or select the known MIDI note (36–84).
4. Click **Match reference WAV** and select a dry, isolated, single-pitched-note WAV. Mono/stereo PCM/float, 8–96 kHz, 0.2–8 seconds and up to 16 MB are accepted. Stereo is downmixed for analysis. Reverb, chords, changing pitch and full songs are outside scope; basic periodicity checks cannot guarantee monophony.
5. Review the returned before/after waveform, cutoff, resonance and all four ADSR controls. **Apply proposal** sends them through existing APVTS host gestures. Play MIDI at the displayed matched note to audition. **Undo change** restores the previous settings. No sound changes before Apply; later knob/automation changes invalidate the waiting result.

Gate timing is supplied, not magically recovered: a sound's release time and the musician's note-off time can be ambiguous from audio alone. For an easy demo choose `ml/runs/reference_match_demo/independent_reference.wav`, set Gate to **800 ms**, leave Auto pitch. This reference was generated by independent SciPy oscillator/filter code, not taken from the training data. It is not evidence of arbitrary real-recording performance.

## Legacy matcher (retained experiments)

The background Python service receives only the chosen local WAV path plus the current parameter snapshot/gate/pitch. No reference audio or path is sent to OpenAI. The saved CNN is not used by this matcher: its constrained training does not cover external recordings. The algorithm is deterministic signal processing plus a small bounded analysis-by-synthesis search:

- Decode/downmix/resample to 24 kHz for comparison, remove DC and trim leading silence using an RMS-envelope threshold. Source WAV bytes remain unchanged.
- Estimate a stable near-equal-tempered pitch using autocorrelation (or use supplied pitch), and estimate an envelope starting point from rise/fall timing.
- Render the actual standalone JUCE synthesizer at 48 kHz: the starting patch plus 4 waveforms × 6 cutoff values, then 27 local cutoff/attack/release refinements of the winning coarse patch: **52 renders** total.
- Score waveform-derived log-mel RMSE plus twice envelope RMSE. RMS/peak alignment is only used inside this comparison representation, not on source files, saved training features or the plugin's output gain. The objective is a technical distance, not perceived quality or a probability.
- Return the lowest-scoring legal candidate, retaining the starting candidate so the reported objective cannot worsen. Exported JUCE parameter bounds are used, including float32 endpoint serialization handling.

The suggested targets are waveform, cutoff, attack and release. Current decay/sustain/resonance/output are preserved; this is a starting patch rather than exhaustive preset recovery. Rendering uses gain 0.8 solely for level-independent comparison/preview; applying a patch does not change the user's output gain. If the current output is muted, the plugin stays muted. Different synthesizers can produce similar sounds with different settings; numeric estimates are not guaranteed to be the source parameters.

The text assistant's Subtle/Medium/Strong selector applies to text suggestions, not the reference search. Match first, apply, then use text to refine the editable sound if desired.

## Artifacts and measured evidence

Each match saves source bytes, requested/rendered parameter manifests, per-stage WAVs/readbacks/logs, matched preview and `result.json` under `ml/runs/reference_matches/`. The result includes renderer identity, initial snapshot, rendering/feature configuration, pitch information, baseline/best score and elapsed wall time. These are generated artifacts ignored by Git. Reference material is local; no new model training or old held-out-set reevaluation occurs.

Independent demo (44.1 kHz stereo, SciPy saw + Butterworth filter, known gate 0.8 s):

- Starting patch: sine, cutoff 12000 Hz, attack 0.005 s, release 0.15 s; remaining defaults.
- Objective: **8.249100204521735 → 1.0399223567908682**.
- Log-mel RMSE: **8.087023513544485 → 1.0192047104841608**.
- Envelope RMSE: **0.08103834548862515 → 0.010358823153353722**.
- Returned patch: saw, cutoff **899.9999389648438 Hz**, attack **0.040468744933605194 s**, release **0.3231770694255829 s**.
- Auto pitch: MIDI **48**. Demo wall time **1.0518315000226721 s**, not a benchmark or real-time claim.
- Full demo measurements: `ml/runs/reference_match_demo/results.json`. Scores can vary with the starting patch's retained parameters; the live C++ integration check used a different snapshot and has its own scores in `build/reference-client-live.log`.

27 Python tests passed, including pitch detection, stereo/rate conversion, silence/noise rejection, level-invariant comparison, source immutability, legal outputs and real renderer search improving the fixed objective. The real C++ async client also received a patch, left live parameters untouched before Apply, applied/undid it, and continued callbacks with zero detected C++ allocations. This proves an integration path, not broad perceptual matching quality.

## Runtime safety and installation

File chooser/UI and snapshot handling are on the message thread. File decoding, pitch/feature work, candidate rendering, filesystem I/O and HTTP handling remain off the real-time audio thread. Existing parameter IDs, processor DSP and state format are unchanged. Requests are bounded and editor closure cancels its client request. Late results cannot overwrite a newer patch.

The backend is running locally during development. The new editor requires installation with Logic closed; a running/saving Logic process blocks replacement. Builds/tests do not constitute in-Logic verification of the newly installed editor.


## Current product matcher v2

`ml/reference_match_v2.py` is separate from the frozen legacy experiments. The local plugin analysis service uses it by default. It scores natural-log mel power with an 80 dB reference-relative floor and fixed nonzero band/activity weighting, plus twice RMS-envelope distance. This reduces silent-bin/quantization influence; it is still a technical heuristic, not a learned perceptual metric or guarantee of human preference. **V2 scores cannot be compared numerically with legacy scores.**

The starting patch and 32 waveform/cutoff candidates are rendered, then two bounded rounds refine three best candidates over cutoff, attack, decay, sustain, release, resonance and waveform. Duplicate vectors are skipped, so the receipt count is reported rather than assuming exactly 52. The hard maximum is 147 renders; current measured ES1 case used 135. Time/gain normalization belongs to comparison only. User gain is excluded from returned updates. Matching runs only in the external worker process, and the editor applies a validated reviewed patch through JUCE gestures.

The current development case uses the already-listened-to ES1 WAV, not an untouched validation set. On that case, under the same v2 objective, the legacy selected patch scores 1.7217783372628326 and the v2 selected patch 1.4076618187798566; envelope RMSE is .1478223119156854→.038692837769691076. No generalization or preference win is established. V2 still has more high-frequency power than this reference. Level-matched Reference/Previous/New listening copies are under `ml/runs/initial_release_listening/`. Human listening acceptance remains pending. No extra training, checkpoint replacement or ONNX deployment followed the negative CNN comparisons.

Both plots use the same dB scale and RMS-aligned comparison representation; raw source WAVs remain unchanged. Total `seconds` includes diagnostics; `search_seconds` isolates matching. An actual in-Logic ES1 request generated and visually verified these files, then passed Apply/Undo with gain 40% preserved. Its score was 3.494→1.315 from this starting patch, not a comparable improvement claim over earlier runs. High-partial and release-shape differences remain visible.
